# 「谛听」百应场控数据采集 WR-P-009-FIX1-TEST-20260921 安装与使用手册

> WR-P-009-FIX1-TEST-20260921 说明：保留直播日期日历和“当天/次日”结束日期选择，开始与结束时间改为人工输入 `HH:MM:SS`。“消耗”与其余累计字段一样，按相同直播间 ID 的历史记录合计进行扣减。系统只允许大于 0 且不超过 24 小时的直播时长，不新增或上传“跨天状态”字段。升级时必须重新运行完整安装包。

适用对象：在场控电脑上使用 Google Chrome 采集百应直播数据，并提交到指定飞书多维表格。

- Windows：Windows 10/11 64 位。

## 推荐：使用一键安装包

现在优先分发下面两个包，不需要再分别发送扩展与桥接压缩包：

- macOS：`diting-WR-P-009-macos.zip`
- Windows：`diting-WR-P-009-FIX1-TEST-20260921-windows.zip`

一键安装器会自动完成：

1. 查找 Google Chrome、Node.js 和 lark-cli。
2. 读取上次安装状态，优先复用已经确认过的绝对路径。
3. 找不到 Node.js 时，从 Node.js 官方地址下载 Node.js 24 LTS 到当前用户目录，不修改系统级环境。
4. 找不到 lark-cli 时，执行飞书官方安装命令。
5. 检查 lark-cli 用户登录；未登录或失效时，引导用户在浏览器完成授权。
6. 用只读命令检查目标多维表权限。
7. 把扩展部署到不会因解压目录被清理而失效的固定位置。
8. 安装 Native Messaging，并写入 Node.js 和 lark-cli 的绝对路径。
9. 保存安装状态，后续重复运行时跳过已有环境。

macOS：

1. 解压 `diting-WR-P-009-macos.zip`。
2. 双击 `安装.command`。

Windows：

1. 解压 `diting-WR-P-009-FIX1-TEST-20260921-windows.zip`。
2. 双击 `setup.cmd`（也可使用 `安装.cmd`）。
3. 根据提示完成一次飞书授权和一次 Chrome 扩展加载确认。

Chrome 的个人版安全策略不允许普通脚本静默安装本地扩展。因此安装器会自动打开 `chrome://extensions/` 和正确的扩展目录，但首次仍需人工点击“加载已解压的扩展程序”。这一步无法在不使用企业策略或 Chrome 应用商店的情况下安全省略。

一键卸载：

- macOS 双击 `卸载.command`。
- Windows 双击 `uninstall.cmd`（也可使用 `卸载.cmd`）。

卸载器只删除：

- 谛听扩展的固定文件目录；
- 谛听安装状态文件。

卸载器不会删除 Node.js、lark-cli、飞书登录凭证或 Google Chrome；即使 Node.js/lark-cli 是安装器补充安装的，也会按此规则保留。

## 安装顺序速览

第一次安装按这个顺序执行：

1. 安装 Node.js LTS。
2. 安装 `lark-cli`。
3. 使用场控人员的飞书账号完成授权，并验证目标表访问权限。
4. 解压并加载 Chrome 扩展。
5. 根据操作系统运行 Mac 或 Windows 桥接安装脚本。
6. 完全退出并重新打开 Chrome。
7. 登录百应，完成一次采集、核算和提交验收。

## 三、安装 Node.js

从 Node.js 官网下载 LTS 版本：

```text
https://nodejs.org/en/download
```

使用默认选项完成安装，然后验证。

macOS 打开“终端”，Windows 打开 PowerShell，执行：

```text
node --version
npm --version
```

两条命令都能显示版本号才可以继续。

如果提示找不到 `node` 或 `npm`，先重启终端；仍然找不到时，重新安装 Node.js LTS。

## 四、安装并授权 lark-cli

### 4.1 安装

在终端或 PowerShell 执行官方安装命令：

```text
npx @larksuite/cli@latest install
```

按向导完成配置。安装后验证：

```text
lark-cli --version
```

如果向导没有完成应用配置，执行：

```text
lark-cli config init --new
```

### 4.2 飞书登录授权

执行：

```text
lark-cli auth login --domain base,drive,contact --scope "wiki:node:read"
```

根据终端提示打开验证地址，用拥有目标多维表编辑权限的飞书账号确认授权。

授权完成后执行：

```text
lark-cli auth status --verify
```

输出中用户身份应为可用状态。

### 4.3 验证目标多维表访问权限

执行以下只读命令，不会写入数据：

```text
lark-cli base +field-list --as user --base-token REPLACE_WITH_TEST_BASE_TOKEN --table-id REPLACE_WITH_TEST_TABLE_ID --format json
```

成功标准：

- 输出包含 `"ok": true`。
- 能看到 `直播间ID`、`直播负责人`、`直播开始时间`、`专业版数据` 等字段。

如果返回无权限，请确认当前飞书账号已加入该多维表并拥有编辑权限，然后重新授权。

## 九、正常使用流程

### 9.1 采集

1. 使用已登录百应的同一个 Chrome 打开直播明细页面：

   ```text
   https://compass.jinritemai.com/talent/live-statement?live_room_id=直播间ID&tab=coreTag
   ```

2. 关闭百应相关页面的开发者工具 DevTools。
3. 点击工具栏中的“「谛听」百应场控数据采集”扩展。
4. 点击“获取并汇总数据”。
5. 等待专业版页面短暂切到前台并自动返回。
6. 当前页面右上角出现“直播数据汇总”即为采集完成。

采集过程中不要手动关闭扩展创建的专业版标签页。

### 9.2 填写提交信息

点击“一键提交飞书”，填写：

- 直播日期：点击日历选择
- 主播名称
- 直播负责人姓名
- 直播状态：整场、断播、重开
- 直播开始时间：人工输入 `HH:MM:SS`
- 直播结束日期：选择“当天”或“次日”
- 直播结束时间：默认填入当前时间，可直接人工修改为 `HH:MM:SS`
- 上传目标：飞书多维表格链接；勾选后可保存为后续默认地址

系统自动生成：

- 直播开始时间：直播日期与输入时间合并
- 直播结束时间：直播日期加“当天/次日”与结束时间合并
- 是否节假日：通过节假日 API 查询后写为“是”或“否”
- 提交人：当前 `lark-cli` 登录用户

如果结束时刻早于开始时刻，系统会自动推荐“次日”。提交时会校验结束时间必须晚于开始时间，且总时长不超过 24 小时；不会生成或上传额外的跨天标识。

日期、月份、时长、ROI、GPM、客单价及转化率等公式字段由多维表自行计算，不在上传 JSON 中。

### 9.3 核算与确认

1. 点击“核算最终数据”。
2. 桥接程序实时查询飞书多维表中所有 `直播间ID` 相同的记录。
3. 系统对下面七个累计字段分别求和并扣减：

   - 成交GMV
   - 累计观看人数
   - 新增粉丝数
   - 直播间曝光人数
   - 商品曝光人数
   - 商品点击人数
   - 成交人数

4. 黄色行代表已扣减后的最终值。
5. 核对无误后，再点击“确认提交飞书”。
6. 页面显示飞书 `record_id` 即为成功。

计算公式：

```text
本次最终值
= 当前百应原始累计值
− 飞书多维表中所有直播间ID相同记录的对应字段合计
```

消耗、停留时长、流量占比、成交粉丝占比等字段不扣减。

## 十、重复提交与异常恢复

一次采集由“直播间 ID + 本次采集时间（含毫秒）”唯一标识。

- 同一份采集结果重复点击：不会新增第二条记录。
- 重新采集后提交：会形成新的打点。
- 记录已创建但截图上传失败：使用原页面相同数据重试，只补传截图。
- 换电脑后：差值仍以飞书全表为准，不依赖原电脑历史。

## 十三、常见问题

### 1. Chrome 显示“无法加载扩展程序”

- 必须先解压 ZIP。
- “加载已解压的扩展程序”时，应选择直接包含 `manifest.json` 的目录。
- 不要把 ZIP 或 CRX 直接拖到扩展页面。

### 2. `Specified native messaging host not found`

- 本机桥接程序没有安装成功。
- Chrome 没有完全重启。
- 扩展 ID 与注册清单不一致。
- 重新运行对应系统的安装脚本，然后完全退出 Chrome。

### 3. `Access to the specified native messaging host is forbidden`

扩展 ID 不正确。正确 ID：

```text
dmfabigojpaodgkkbhnceellgffalcij
```

移除错误扩展，重新加载 WR-P-009-FIX1-TEST-20260921。

### 4. `env: node: No such file or directory`

安装的是旧桥接程序，或者安装时没有识别 Node 路径。

1. 确认 `node --version` 正常。
2. 重新运行 WR-P-009-FIX1-TEST-20260921 Windows 安装脚本。

### 5. 找不到 lark-cli

执行：

```text
lark-cli --version
```

如果失败，重新执行：

```text
npx @larksuite/cli@latest install
```

然后重新运行桥接安装脚本。

### 6. 飞书授权过期或无权限

提交弹窗会区分两类情况：

- 自定义 Wiki 地址缺少 Scope：点击“重新授权”，在自动打开的飞书页面确认，然后回到弹窗点击“我已完成授权”。默认直连 Base 地址不依赖外层 Wiki 节点解析。
- 当前账号没有目标文档权限：联系文档所有者添加权限后重试；重新登录不能绕过文档权限。

如需手动处理，可在终端执行：

```text
lark-cli auth login --domain base,drive,contact --scope "wiki:node:read"
lark-cli auth check --scope "wiki:node:read" --json
lark-cli auth status --verify
```

默认表请以 `base +field-list --as user` 能否读取字段为准。默认表字段读取成功后，即使旧 Wiki 外层节点无法解析也不会阻止安装。用户填写其他 Wiki/Base 地址时，仍以 `base +url-resolve --as user` 是否成功为准。

### 7. 提示“当前原始值小于多维表同 ID 记录合计”

说明相同直播间 ID 的历史记录中可能存在：

- 重复记录；
- 没有按差值写入的旧记录；
- 手动修改后的错误数据。

先在飞书中筛选该直播间 ID，检查七个累计字段，修正后重新核算。不要直接绕过校验，
否则可能写入负数。

### 8. 专业版或流量数据未获取

- 确认百应登录未过期。
- 关闭相关页面 DevTools。
- 采集时不要切换或关闭临时专业版标签页。
- 允许扩展短暂把专业版页面切到前台。
- 使用“复制诊断信息”查看缺失接口。

### 9. 截图上传失败

- 确认飞书授权包含 Base 与 Drive。
- 确认目标表的 `专业版数据` 仍是附件字段。
- 更新到最新桥接程序后，用同一份采集结果重试。

## 十五、安全说明

- 桥接程序由 Chrome 按需静默启动，不会弹终端。
- 扩展只能调用固定名称的 Native Messaging Host。
- 桥接程序只接受固定动作和字段白名单，不能执行扩展传入的任意命令。
- 飞书目标 Base、Table 和截图字段写在本机私有配置中。
- lark-cli 授权保存在当前系统用户目录，不要复制给其他人。
- 场控人员离职或电脑交接时，应执行 `lark-cli auth logout` 并卸载桥接程序。
