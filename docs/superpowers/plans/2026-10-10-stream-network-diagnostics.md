# 直播链路只读诊断与恢复提示

用户已同意按直播源网页和服务器收流两端区分故障；OBS 始终不受本功能控制，指标采集上传独立。

## 范围与证据
- 插件只读观察已绑定、同主播的大屏 HTML video/audio：网络离线提示、播放/暂停、静音、错误、播放进度。连续15秒进度不推进才标记停滞；多播放器或无法读取则未知，不猜原因。刷新不是自动动作。
- 公网复盘页沿用10秒场次查询。通过本页连续成功查询观察已登记录像末尾是否增长；连续3分钟不增长提示收流/录像处理待检查，不能断言 OBS 网络断开。查询失败或超过30秒没有成功查询则服务器状态未知，不用旧数据宣布正常。
- 切换场次、长时间后台/休眠后重新观察；不依赖两台电脑的时钟对齐。
- 源状态只在相同推流电脑和浏览器、绑定主播匹配时有效。只读状态消息无需点击；刷新依旧要求用户点击，30秒限流，不可调用上传。
- 网络离线、后端查询失败或录像停更时不给“刷新即可恢复”的提示；对应提醒引导检查网络/OBS自动重连/服务日志。源播放器卡住时才建议确认刷新。
- 打开历史已结束场次仅保留历史静音证据，不诊断当前源页面；观察中的直播转为结束时提醒确认是否正常停播。

## 实施步骤
1. 先增加失败测试：源播放推进/停滞/暂停/静音/离线/未知；状态通道来源校验与不上传；服务器增长/失败/停滞/重选和休眠；提示与刷新门禁。
2. 扩展 source-control.js / source-refresh.mjs / review-bridge.js，新增 SOURCE_HEALTH 白名单，只返回归一化状态及时间，不返回页面内容或凭据。旧刷新权限不变。
3. 在已有 audio-health.mjs 中加入只读请求、收流观察器和诊断函数；app.mjs 使用现有查询，新增简洁链路状态区，将对应故障接到现有提醒窗。拒绝过期、跨场次响应。
4. 插件升级0.4.4并打包，更新README。测试只使用离线fixtures，不产生业务数据。
5. 运行完整Node回归、语法/包校验；用真实历史场次只读检查页面。提交并推送GitHub、GitLab，服务器通过Git快进拉取，仅前端静态文件生效，不重启任何服务。

## 验收限制
无需新后端或服务重启。无法自动读取OBS所选窗口或跨电脑控制；网页播放进度推进不证明声音正常；服务器录像未增长也可能是处理延迟。Windows实播恢复仍需实测。
